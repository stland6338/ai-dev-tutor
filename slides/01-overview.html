今とこれから

毎回承認して見張る開発から、目標を渡して任せる開発へ

今: 毎回承認して見張る

  • 編集やコマンドのたびに確認が出る（Manual）
  • 「直しました」という報告を、人が後から確かめる
  • 「push しないで」と会話で頼む。compact でその発言が消えると効かない
  • 1つのセッションに人が付きっきりになる
→

これから: 目標を渡して任せる

  • auto mode: 分類モデルが操作を審査し、危険なものだけ止める
  • /goal と Stop hook: テストが通るまで終われない
  • deny ルール・hook・sandbox: 禁止は注意ではなく仕組みで
  • worktree・クラウドで並べ、人はレビューと判断をする

前提: 1つのセッションを信頼できてから並べる。確かめ方（A3）と守り（A6）が無いと、確かめていない変更が並列に増える。

任せられる

/goal と auto mode で、完了条件まで自律実行

完了条件の書き方（A3 の例）

/goal ISSUE.md のバグが直り、npm test が終了コード 0 で通る。test/ の期待値は変えない。20 ターンで止める
終わりの状態確かめ方変えてはいけないもの回数の条項

判定役のモデルはコマンドを実行せず、ファイルも読まない。会話に出た出力で示せる形で書く。

動き方

  1. 先に Shift+Tab で auto mode にする。/goal は権限モードを変えないので、Manual のままだと npm test のたびに確認が出る
  2. /goal を設定した時点で、その条件を指示として1ターン目が始まる
  3. ターンごとに小さなモデルが条件を判定し、満たすまで続けさせる
  4. auto mode では分類モデルが操作を審査し、危険なものだけ止める（v2.1.283 から起動時の既定）

時間ではなく、合否を判定できる完了条件を渡す。D02 では「夜間実行が何も終えない」ときの対処として挙げている。

安全に任せる

権限モードで手間を減らし、deny ルールと hook で必ず止める

権限モード（確認なしで動くもの）

モード動き
default読み取りだけ。編集やコマンドは確認
acceptEdits読み取り・ファイル編集・よく使うファイル操作
plan計画を承認するまでソースを編集しない
auto分類モデルが審査し、危険なものだけ止める
dontAsk許可リストにないものは確認せず拒否（headless 向け）
bypassPermissions確認なし。隔離された環境以外では使わない

auto mode は3回続けて、または合計20回止めると一時停止し、確認ありに戻る

CLAUDE.mdClaude の注意に頼る。破っても大きな害がないことに
deny ルールどのモードでも効く。allow より優先
"deny": ["Bash(git push *)"]
PreToolUse hookスクリプトが直前に走り、終了コード 2 で理由付きで止める
sandbox書き込める場所と通信先を OS レベルで制限し、被害の範囲を絞る

既定が auto でも、deny ルール・hooks・sandbox を重ねる考え方は変わらない

並列とクラウド

手元で並べ、クラウドに渡し、決まった時刻に動かす

worktree

手元で並べる

claude -w add-search
  • 作業ごとに checkout とブランチを分け、互いに干渉させない
  • 書いたセッションとは別のセッションにレビューさせる
  • 並列のタスクはファイルの境目で分ける
cloud sessions

クラウドに渡す

  • タスクごとに新しい VM。手元で計画し、クラウドで実装し、teleport で戻す
  • 依頼は確かめ方まで書いた自己完結したチケットにする
  • 「npm test を30回続けて回して証明して」に、40回回して失敗0を示した例がある
scheduled tasks

時刻やイベントで動かす

  • スケジュール（最短で毎時）・HTTP エンドポイント・GitHub のイベントで起動し、毎回 cloud session として動く
  • 承認の確認なしで動き、既定では claude/ で始まるブランチに push する
  • 手元で動かすなら Desktop や /loop

pstack の README の標語

関連する章D02 Grok Bot の環境を整える

1日の流れの例

朝に目標を渡し、昼にレビューし、夜は自動で直させる

これは各章の仕組みを組み合わせた一例です。決まった手順ではありません

朝目標を渡す
  • plan mode で計画を立ててコミットする（A2）
  • 背景・やること・確かめ方を書いたチケットを、cloud session や worktree に配る（A7・A8）
  • 各セッションに /goal で完了条件を渡す（A3）
昼レビューする
  • 書いたセッションとは別の context や /code-review にレビューさせる（A3・A7）
  • 人の承認の数は、変更のリスクで決める（A7）
  • 結果を teleport で手元に移し、npm test で確かめる（A8）
夜自動で直させる
  • Auto-fix・/autofix-pr で、失敗したチェックやレビューコメントに対応させる（A8）
  • あいまいな点や設計に関わる点は、Claude が人に聞く（A8）
  • scheduled tasks や Grok Bot のルーティンで、翌朝の点検を回す（A8・D02）
