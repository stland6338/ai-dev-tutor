## A. Anthropic

### A1. Claude Code との協働開発
- コンテキストが最大の制約。`/clear`（無関係タスク間）、`/compact <指示>`、`Esc Esc`/`/rewind` の部分要約、`/btw`（履歴に残らない質問）、`/context`
- 検証手段を渡す（テスト・ビルド・スクショ）。強制力の段階: プロンプト内の指示 → `/goal` → Stop hook → reviewer subagent / `/code-review`
- Explore → Plan → Implement → Commit。plan mode は `Shift+Tab` / `claude --permission-mode plan`、`Ctrl+G` で計画をエディタ編集。1文で diff を説明できるなら plan 省略可
- CLAUDE.md: `/init`、短く（「消したら間違えるか？」で判定）、`@path` import、`CLAUDE.local.md`、`.claude/rules/*.md` の `paths:` frontmatter、CLAUDE.md が無ければ `AGENTS.md` を読む、`/doctor`
- Auto memory: `~/.claude/projects/<project>/memory/MEMORY.md`（先頭200行/25KB を毎回読込）、`/memory`、`"autoMemoryEnabled": false`
- 拡張の使い分け: hooks（必ず実行・決定的）/ skills（`.claude/skills/<name>/SKILL.md`、副作用あり workflow は `disable-model-invocation: true`）/ subagents（`.claude/agents/*.md`、`isolation: worktree`）/ plugins（`/plugin`）/ `claude mcp add`
- 権限モード: `default`(Manual) `acceptEdits` `plan` `auto` `dontAsk` `bypassPermissions`。`/permissions`、`/sandbox`
- 並列: `claude -w <name>` → `.claude/worktrees/<name>`・branch `worktree-<name>`、`.worktreeinclude`、Writer/Reviewer、`/batch`
- Headless: `claude -p --output-format json|stream-json --verbose --allowedTools ... --permission-mode dontAsk`
- 2026 新機能: `/goal <条件>`（v2.1.139、`/goal clear`、`-p` 可）、auto mode（標準化の時期はページ間で記述が食い違う [U]）、`claude agents`（preview）、cross-session messaging、`/verify`、agent teams（実験的）、hook event 追加（`PostToolBatch` `PreModelSwitch` `WorktreeCreate`）

演習ネタ:
- hook [V]: `{"hooks":{"PostToolUse":[{"matcher":"Edit|Write","hooks":[{"type":"command","command":"..."}]}]}}`。PreToolUse で `"if":"Bash(rm *)"`。stdin JSON（`tool_name`, `tool_input.command`）、`exit 2` でブロック＋stderr を Claude へ、`exit 1` は非ブロック。JSON 出力 `hookSpecificOutput.permissionDecision: "deny"`
- permissions [V]: `{"permissions":{"allow":["Bash(npm run *)"],"deny":["Bash(git push *)"]}}`
- skill [V]: frontmatter `name` `description` `disable-model-invocation: true`、本文で `$ARGUMENTS`、`/fix-issue 1234`
- headless fan-out [V]、`claude -p "/goal ..." --output-format stream-json --verbose` [V]

- Building effective agents（2024-12-19）: workflow vs agent。prompt chaining / routing / parallelization / orchestrator-workers / evaluator-optimizer / autonomous agent。シンプル・透明・ACI 設計

- 実行基盤: Agent SDK（`pip install claude-agent-sdk` / `npm install @anthropic-ai/claude-agent-sdk`、`.env` は読まない）/ client SDK + tool runner / Managed Agents / `claude -p`

Agent SDK 最小例 [V]:
```python
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, ResultMessage
async def main():
    async for m in query(prompt="Review utils.py for crash bugs and fix them.",
        options=ClaudeAgentOptions(allowed_tools=["Read","Edit","Glob"], permission_mode="acceptEdits")):
        if isinstance(m, ResultMessage): print("Done:", m.subtype)
asyncio.run(main())
```

### B2. xAI API
- **Responses API（`POST /v1/responses`）推奨。Chat Completions は非推奨**（暗号化 reasoning を運べない）
- reasoning item を毎ターンそのまま返す: `previous_response_id`（store on）か `store:false` で `response.output` 全体を次 input に追記。`output_text` だけ・並べ替え・フィルタは不可
- caching は自動。会話ごと `prompt_cache_key`（SDK は `x-grok-conv-id`）。追記のみ・静的内容を先頭。`usage.input_tokens_details.cached_tokens`
- `reasoning.effort` を毎回明示、streaming 推奨、timeout ≥900s、`max_output_tokens` は可視出力のみ
- **`temperature=0.7` / `top_p=0.95` から大きく外さない**
- server-side tools: `web_search`（allowed/excluded_domains 各5）、`x_search`（allowed_x_handles, from_date, to_date）、code execution（OpenAI 形式 `code_interpreter` / xAI SDK `code_execution`）、collections search、remote MCP、画像生成。自前 function と混在可
- function calling は常に schema 準拠（strict 暗黙 true）。structured outputs: Responses `text.format`、`client.responses.parse(text_format=Model)`、xAI SDK `chat.parse(Model)`
- OpenAI SDK 互換（`base_url="https://api.x.ai/v1"`）。`POST /v1/messages`（Anthropic 互換）は OpenAPI にのみ記載 [U]。`/v1/responses/compact`、Batch、`service_tier:"priority"`

```python
import os; from xai_sdk import Client; from xai_sdk.chat import user
chat = Client(api_key=os.getenv("XAI_API_KEY")).chat.create(model="grok-4.7")
chat.append(user("Fix the bug: function median(a){a.sort();return a[a.length/2]}"))
print(chat.sample().content)
```

### G1. security（code.claude.com/docs/en/security）[V]
- auto mode（分類モデルが審査）と Manual（読む操作以外は確認）。auto は対話の terminal と VS Code の既定の開始モード
- curl・wget など Web から取るコマンドは既定で自動承認しない。WebFetch は多くの場合、別のモデルで要約した結果を渡す
- 信頼していないフォルダでは信頼の確認の画面。`.mcp.json` は別に承認。`-p` ではどちらも出ない
- untrusted な内容の5か条: コマンドを確かめてから承認、信頼できない内容を直接流し込まない、大事なファイルの変更を確かめる、VM でスクリプトとツール呼び出し、怪しい振る舞いは `/feedback`
- 「提案されたコードとコマンドを承認前に確かめるのは使う人の責任」。`/security-review`、security-guidance プラグイン、`/permissions` を定期的に見直す

### G2. sessions（sessions）[V]
- `claude --continue` / `--resume [名前|transcript]` / `--from-pr <番号>` / `/resume`。一覧で `Ctrl+A`（全プロジェクト）・`Ctrl+W`（全 worktree）・`Ctrl+R`（名前変更）
- 名前: `claude -n <名前>`、`/rename`。名前が無くても最初の依頼から要約したタイトルで再開できる
- 分岐: `/branch [名前]`、`claude --continue --fork-session`。分岐せずに2つのターミナルで再開すると会話が混ざる
- `/export [ファイル]`。保存は `~/.claude/projects/<project>/<session-id>.jsonl`、既定30日（`cleanupPeriodDays`）。JSONL の形式は内部のもの

### G3. debug-your-config [V]
- まず `/context`。`/memory`・`/skills`・`/hooks`・`/mcp`・`/permissions`・`/doctor`・`/debug [問題]`・`/status`。シェルから `claude doctor`
- `claude --safe-mode`（CLAUDE.md・skills・プラグイン・hooks・MCP などを切る）、`claude --debug`、`claude --debug=mcp`
- よくある原因: matcher が配列・小文字、hooks を単独のファイルに書く、`~/.claude.json` に設定を書く、settings.local.json の上書き、skill をフォルダに入れない、`.mcp.json` を `.claude/` に置く・`servers` キー、Bash の deny は文字列で合わせる

### G4. setup（更新）[V]
- 公式のインストーラーは裏で自動更新。`claude update`、`claude doctor` に最後の更新の結果
- `autoUpdatesChannel`: `latest`（既定）/ `stable`（約1週間遅れ、大きな不具合の版を飛ばす）。`/config` の Auto-update channel
- `minimumVersion` で下限、`DISABLE_AUTOUPDATER`（`claude update` は使える）、`DISABLE_UPDATES`（全部止める）。Homebrew・WinGet は自動更新しない（`CLAUDE_CODE_PACKAGE_MANAGER_AUTO_UPDATE=1` で任せられる）
- 新しいモデルが stable より新しい版を必要とすることがある
